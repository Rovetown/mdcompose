# Editor and IDE integrations

Each directory here is one integration: a thin wrapper that runs the `mdcompose`
command line and shows its results inside an editor. None of them changes
`mdcompose/core/`. Nothing here is built yet; this directory holds the shared
contract that every integration will follow.

    integrations/
      contract/   sample JSON reports, generated by the real command line
      vscode/     planned: VS Code, VSCodium, and Cursor (one package)
      jetbrains/  planned
      neovim/     planned

The evidence for which editors get an integration, and in what order, is in
[`docs/editor-integrations.md`](../docs/editor-integrations.md). Editors not
listed there are served by running the command line from a terminal.

## Rules every integration follows

- **A wrapper, not a second implementation.** It runs `mdcompose`, reads the JSON
  reports, and renders them. It offers only what the command line offers, so there
  is no create or add action.
- **One contract.** It reads only the fields listed in `contract/` and ignores the
  rest. The test suite fails if the command line stops carrying a listed field.
  The contract is described in section 24 of
  [`docs/core-contract.md`](../docs/core-contract.md).
- **Reports use the global JSON option before the command**, for example
  `mdcompose --json doctor`. A report that finds a condition to resolve exits 1 and
  still prints its document, so a reader parses the document on exit code 0 and 1.
- **No network, no telemetry.** An integration never makes a request of its own.
- **Locating the command line.** A user setting first, then the executable search
  path, then a clear "not found" message. An integration never installs or
  updates the command line.
- **Caches are display only**, kept in the editor's own storage area and never in
  the library, the project, or any directory mdcompose owns.
- **Version range.** Each release declares the lowest and highest command line
  version it was tested against and checks `mdcompose --version` once at start.

## Layout of one integration

Each `integrations/<editor>/` directory is self-contained: its own build files,
lockfile, tests, changelog, and version, independent of the command line's.

## Release tags

An integration release tag is `integration-<editor>-v<version>`, for example
`integration-vscode-v0.1.0`. It must not begin with the letter `v`: the command
line's release workflow starts on any tag that does, so a tag such as
`vscode-v0.1.0` would start a release of the command line. Command line tags stay
`v<version>`.

Publishing is always started by hand and never runs on a push. Registry tokens
live in repository secrets or the maintainer's own environment, never in the
repository.
